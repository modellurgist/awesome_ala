# Contributing to Awesome ALA

Thanks for helping build a shared index of Abstraction Layered Architecture explorations. Anyone can add an entry — you don't need to be an ALA expert, and entries that question or stress-test ALA are as welcome as ones that champion it.

## What belongs here

Links to things others can **read or run**: apps, design write-ups, tools, analyses, blog posts, talks. Pick the section that fits best:

- **Web Apps** — runnable applications built or refactored to ALA.
- **Designs & Patterns** — design write-ups, notations, reusable patterns (the *how*, not one specific app).
- **Tools** — linters, generators, analyzers that check or produce ALA.
- **Analysis** — measurements, comparisons, critiques; evidence for or against ALA's claims.
- **Thoughts & Writing** — blog posts, essays, opinions, talks.

If something fits two sections, pick the primary one; don't list it twice.

## How to add an entry

1. Fork the repo and edit `README.md`.
2. Add **one** line to the chosen section, in this form:

   ```
   - [Name](https://link) — One-line description. *(language / stack, if relevant)*
   ```

3. Open a pull request.

### Style

- **One line per entry**, one entry per link. Keep the description to a single sentence describing what it *is*, not marketing.
- Link to something **public and durable** — a repo, a live site, an article. No paywalled or login-only links.
- Note the **language / stack** in italics when relevant, e.g. `*(Elixir / Phoenix)*`, `*(C#)*`, `*(Rust)*`.
- Keep entries roughly **alphabetical** within their section.
- Self-submissions are fine — most entries are. Just describe your own work plainly.

## Not a fit

- Broken, dead, or login-walled links.
- Duplicate entries, or the same project listed in several sections.
- Content unrelated to ALA. (Related architectural ideas are fine *if* the entry explains the ALA connection.)
